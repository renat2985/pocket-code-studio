# Pocket Code Studio

**Файлы вашего сервера. Привычная среда для кода. Один PHP-файл.**

Файловый менеджер и браузерный редактор кода для собственного сервера с интерфейсом, вдохновлённым Visual Studio Code. Загрузите `filemanager.php`, войдите, смените начальный пароль и управляйте сайтом через браузер.

## Почему Pocket Code Studio?

- **Один файл приложения:** не нужны база данных, Composer, сборка Node.js или мастер установки приложения.
- **Привычная рабочая среда:** дерево файлов, внутренние вкладки, компактные меню File / Edit / View / Tools / Help, минимап и строка состояния.
- **Темы всего интерфейса:** редактор, список файлов, меню, диалоговые окна и полосы прокрутки следуют выбранной палитре.
- **Бережное сохранение файлов:** проверка версии, проверенная запись и приватная резервная копия перед заменой отредактированного файла.
- **Git только для чтения:** просмотр изменённых файлов и сравнение текста редактора с последним коммитом.

Приложение независимо от Microsoft. Оно использует Ace, а не движок Visual Studio Code, и не запускает расширения VS Code.

## Требования

- PHP **7.4+** с сессиями и стандартными функциями файловой системы, хеширования и JSON; рекомендуется поддерживаемая версия PHP.
- Apache, Nginx или другой сервер с поддержкой PHP. HTTPS обязателен, кроме локальной разработки через loopback-адрес.
- Доступная для записи рабочая папка и приватное хранилище временных файлов и сессий PHP с правом записи.
- Доступ браузера к интернету для текущих JavaScript/CSS-зависимостей, загружаемых с CDN. **Развёртывание одним файлом не означает полностью автономную работу.**
- Необязательно: Git в серверном PATH и разрешённый PHP `proc_open` для просмотра статуса и сравнения Git.
- Необязательно: расширения или инструменты для нужных форматов архивов. Доступность зависит от хостинга.

## Быстрый старт

1. Скачайте `filemanager.php` из этого репозитория. Это **единственный файл приложения**, который нужно загрузить на сервер.
2. Начальный пароль — **`admin123`**. Войдите и сразу смените его через **File → Settings → Change password**, прежде чем открывать публичный доступ к менеджеру. В файле хранится хеш, а не открытый пароль. Поля имени пользователя нет.

   Чтобы задать уникальный пароль до развёртывания, создайте хеш локально и замените `$authPasswordHash` в начале PHP-файла:

   ```sh
   php -r 'echo password_hash(readline("New password (input is visible): "), PASSWORD_DEFAULT), PHP_EOL;'
   ```

   Не публикуйте хеш пароля своей рабочей установки в открытом репозитории.

3. Проверьте `$config['root_path']`. По умолчанию используется корневая папка веб-сервера. Ограничьте её директорией, которой собираетесь управлять.
4. Загрузите настроенный PHP-файл. Предоставьте учётной записи веб-сервера только необходимые права доступа к файловой системе.
5. Откройте файл по HTTPS и войдите с паролем из шага 2.

При использовании TLS на Apache/Nginx PHP должен получать корректный серверный параметр `HTTPS=on`. Произвольные заголовки перенаправления, присланные клиентом, не считаются доверенными.

Пример локального запуска с начальным или собственным настроенным паролем:

```sh
php -S 127.0.0.1:8080
```

Откройте `http://127.0.0.1:8080/filemanager.php`. Позже пароль можно сменить через **File → Settings → Change password**. Для этого учётная запись веб-сервера должна иметь возможность заменить `filemanager.php`; при ошибке прежний пароль остаётся действующим.

## Работа с файлами

Раскрывайте папки в левом проводнике и нажимайте на файл, чтобы открыть его во внутренней вкладке. Перетаскивайте границу боковой панели для изменения ширины. Вкладки и позиции курсора восстанавливаются после перезагрузки; **содержимое несохранённых документов в cookie не хранится**.

Используйте **File → Save** или Ctrl/⌘ S для сохранения, **Edit → Find / Replace** для поиска и **View** для переключения минимапа и переноса строк. Форматирование запускается отдельной командой **Tools → Format document**; сохранение не форматирует код автоматически. Язык и размер шрифта выбираются в нижней строке состояния. Тема интерфейса выбирается через **View → Color theme**. Поиск файлов находится по центру верхней панели, **Sign out** — у правого края.

## Сохранение настроек

Выпадающий список часовых поясов показывает смещение UTC и текущее время для выбранной зоны. Зона, определённая браузером, предлагается кнопкой **Use browser timezone** и никогда не применяется автоматически. Подтвердите выбор через **Save Settings** или отмените его кнопкой **Cancel**.

Настройки и необязательная смена пароля объединены в одну форму с общими кнопками **Cancel / Save Settings**. Оставьте все поля пароля пустыми, чтобы сохранить прежний пароль. Для смены укажите текущий пароль и два совпадающих новых. Все значения проверяются до единой замены конфигурации; ошибка любого поля оставляет и настройки, и пароль без изменений. Cancel отменяет правки в форме. Сохранение не перезагружает рабочую среду и не сбрасывает открытые правки редактора.

**File → Settings** сохраняет часовой пояс, формат даты PHP и размер шрифта интерфейса прямо в `filemanager.php`, рядом с настройкой пароля. Значения хранятся как JSON-данные в base64, а не исполняемый PHP-код. Допустимый размер шрифта — 10px–32px; часовой пояс и формат даты проверяются перед сохранением.

Для сохранения настроек нужны права на замену файла приложения. Изменение пароля и настроек использует общую блокировку, проверенную приватную резервную копию, проверенный временный файл и атомарную замену. Если запись не удалась, оригинал остаётся целым. При обновлении приложения сохраняйте отдельную копию своих настроек и конфигурации пароля.

Существующий `.fm-config` читается для совместимости, пока настройки не сохранены в PHP-файле. Следующее успешное сохранение через Settings перенесёт действующие значения в `filemanager.php`; новый `.fm-config` не создаётся. Старый файл остаётся нетронутым, и его можно удалить после проверки перенесённых настроек.

## Мобильный интерфейс

На экранах шириной до 760 px кнопка **Files** открывает проводник на всю ширину, **List** — таблицу файлов, а вкладка редактора занимает доступную ширину. Компактное меню **☰** содержит существующие команды, выбор темы и поиск файлов. Открытые файлы доступны через горизонтальную строку вкладок и выпадающий список; возврат к проводнику сохраняет его положение прокрутки.

На телефоне по умолчанию включён перенос строк и скрыт минимап; предпочтение минимапа хранится отдельно от настройки компьютера. Скрываемая строка клавиш предоставляет Tab, уменьшение отступа, фигурные и круглые скобки, отмену и повтор. Нажмите **⌨**, чтобы переключить эту строку, и **…** в строке состояния, чтобы открыть дополнительные настройки редактора. Изменения видимой области подстраивают рабочую среду при открытии экранной клавиатуры и удерживают активный курсор в поле зрения. Диалоги и поиск редактора адаптированы к узкому экрану. На широких экранах сохраняется настольная навигация.

## Сравнение Git

Настроенный корень рабочей папки должен совпадать с корнем Git-репозитория. В списках файлов отображаются метки статуса; откройте файл и выберите **Tools → Git: View changes against HEAD**, чтобы увидеть единое сравнение с последним коммитом, включая несохранённый текст. Новые файлы сравниваются с пустым документом.

Интеграция **не предоставляет действий stage, commit, checkout, reset, push или pull**. Если Git или `proc_open` недоступен, просмотр файлов продолжает работать, а окно сравнения показывает объяснение. Репозитории в родительских папках и полоски изменений возле номеров строк пока не поддерживаются.

## Безопасность и сохранение файлов

Любой доступ **через `filemanager.php`** требует авторизации: получение списков, поиск, скачивание, загрузка, чтение и запись в редакторе. При этом обычный публичный сайт остаётся публичным; доступ по прямым URL регулируется настройками веб-сервера.

- PHP-файл хранит результат `password_hash()`. Идентификатор сессии обновляется при входе и смене пароля; смена пароля делает остальные сессии недействительными.
- Cookie используют HttpOnly, SameSite=Strict и Secure при HTTPS. Сессии истекают после 30 минут бездействия или 12 часов общей продолжительности.
- Каждый POST требует CSRF-токен, связанный с сессией. Изменяющие данные GET-запросы отклоняются. Попытки входа ограничены по адресу и суммарно.
- При сохранении проверяются переданное число байтов и SHA-256 версии файла на диске. Конфликт версий блокирует замену, а текст остаётся доступен в редакторе.
- Перед заменой изменённого файла проверяется приватная резервная копия вне корня сайта. Новые байты записываются и проверяются во временном файле в той же папке перед переименованием. Сохранения из редактора выполняются последовательно.
- Сохраняются UTF-8 BOM и единые окончания строк LF/CRLF/CR. Редактор отказывается обрабатывать бинарные файлы, текст не в UTF-8, смешанные окончания строк, жёсткие ссылки и файлы больше 8 МБ.

Приватные резервные копии создаются в `sys_get_temp_dir()/fm-editor-<workspace hash>/`; данные авторизации используют отдельную приватную временную папку. Хостинг может очищать временное хранилище. Эти копии **не заменяют постоянные резервные копии**. Внешние программы, игнорирующие блокировку редактора, всё ещё могут одновременно изменить файл во время замены; специфичные для файловой системы ACL и расширенные атрибуты могут не сохраниться. Сохранение не проверяет синтаксис вашего кода.
